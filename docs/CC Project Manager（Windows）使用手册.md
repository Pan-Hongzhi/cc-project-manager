# CC Project Manager（Windows）使用手册

适用版本：**M1（只读版）0.1.0** · 2026-09-23

CC Project Manager 是一个 Windows 桌面小工具，用来看清 Claude Code（下称 CC）在本机留下的项目状态：哪些项目最近在用、各占多少空间、用了多少 token、哪些是孤儿或残留数据。

**M1 版本只读，不会修改、移动或删除 `.claude` 目录里的任何文件。** 删除项目（purge）、记忆迁移、导出导入等写操作属于后续版本。

---

## 1. 这个版本能做什么

| 能做 | 不能做（后续版本） |
| --- | --- |
| 列出全部 CC 项目，按最近活跃排序 | 删除项目（purge） |
| 标出项目状态：正常 / 仅配置 / 孤儿 / 路径不可达 / 无主数据 / 旧编码残留 | 迁移或重绑定记忆 |
| 识别哪些项目正在运行 CC，且能排除僵尸文件和 PID 被复用的情况 | 导出 / 导入记忆 zip |
| 按类别统计 `.claude` 空间占用，标注每类的清扫策略和删除后果 | 按类别删除转录 |
| 统计每个项目现存转录的 token 用量 | 记忆内容编辑与搜索 |
| 展示 CC 自己的全局 token 统计（/usage 口径） | 费用金额估算 |
| 模拟「下次自动清扫会删掉多少」 | 日志文件 |
| 一键在项目目录打开 CC 新会话或恢复会话 | |
| 打开项目目录、数据目录、/insights 报告 | |
| 诊断页：数据根、CLI、编码自校验、会话文件判定 | |

## 2. 安装与启动

### 2.1 直接运行 exe（推荐）

1. 找到 `target\release\cc-project-manager.exe`（约 9 MB）。
2. 双击运行，或把它拷到任意位置再运行。不需要安装，只依赖 Windows 11 自带的 WebView2。
3. 第一次启动会自动做一次全量扫描，几秒后界面出现数据。

也可以用安装包：`target\release\bundle\nsis\CC Project Manager_0.1.0_x64-setup.exe`。

### 2.2 开发模式运行

在项目目录打开一个**新的** PowerShell 窗口：

```powershell
cd C:\Users\alice\Desktop\work\win_project\cc-project-manager
npm run tauri dev
```

如果提示找不到 `cargo`，先执行：

```powershell
$env:Path += ";$env:USERPROFILE\.cargo\bin"
```

### 2.3 重新构建 exe

```powershell
npm run tauri build
```

首次约 3～5 分钟，产物在 `target\release\cc-project-manager.exe`。

## 3. 界面总览

窗口分三部分：顶部**状态栏**、三个**标签页**（项目 / 全局 / 诊断）、右侧**详情面板**（仅项目页）。

### 3.1 状态栏（始终可见）

从左到右：

| 项目 | 含义 |
| --- | --- |
| 数据根 | CC 数据目录，通常是 `C:\Users\<你>\.claude`。后面的小标签说明来源：「默认位置」或「CLAUDE_CONFIG_DIR」（设置了环境变量） |
| CLI 标签 | 绿色 = 找到了 `claude` 命令并显示版本；红色 = 没找到（不影响本版本的只读功能） |
| 编码自校验 | 绿色「通过」= 数据目录名都能对应到配置项；黄色「未通过」= 有解释不了的目录，见第 6 节 |
| 扫描信息 | 「上次扫描 N 前 · 合计 X MB」= 显示的是缓存结果；「本次扫描 刚刚」= 刚扫完 |
| 重新扫描 | 触发全量扫描，约 3 秒，下方出现进度条 |

启动时先显示上次扫描的缓存结果，所以打开即有数据；想要最新数字就点「重新扫描」。

## 4. 项目页

### 4.1 列表

每行一个项目，默认按**最近活跃**降序。列含义：

| 列 | 含义 |
| --- | --- |
| 状态 | 见 4.2；运行中的项目额外带蓝色「运行中」标签 |
| 项目路径 | 真实路径（正斜杠形式，与 CC 配置文件一致）。无主数据没有真实路径，显示灰色的数据目录名 |
| 最近活跃 | 该项目转录文件的最后修改时间，如「刚刚」「3 小时前」「19 天前」。仅配置的项目没有转录，显示「—」 |
| 空间 | 该项目数据目录总大小 |
| token（现存转录） | 现存转录里 assistant 消息的 token 总和（输入 + 输出 + 缓存写入 + 缓存读取）。转录会被 CC 30 天清扫，所以这不是历史总量 |
| 会话数 | 顶层转录文件数，即会话数 |

### 4.2 项目状态

| 标签 | 含义 | 常见原因 |
| --- | --- | --- |
| 正常（绿） | 配置项、真实路径、数据目录三者齐全 | 正常项目 |
| 仅配置（灰） | 有配置项和真实路径，但没有数据目录 | 在某个目录启动过 CC 但没聊过，例如 `C:/Windows/System32` |
| 孤儿项目（红） | 配置项还在，真实路径已不存在 | 项目文件夹被删除或移动 |
| 路径不可达（黄） | 真实路径在网络盘或 UNC 上，2 秒内探测不到 | 网盘离线、VPN 未连 |
| 无主数据（黄） | 数据目录存在，但配置文件里没有对应条目 | 配置被手动清理过 |
| 旧编码残留（蓝） | 数据目录是旧版本 CC 用旧编码规则生成的，同一项目还有新目录 | CC 升级后目录名规则变化 |

### 4.3 筛选与排序

- 左侧下拉框筛选：全部 / 运行中 / 长期未用且占用大 / 孤儿项目 / 路径不可达 / 无主数据 / 旧编码残留 / 仅配置。
- 选「长期未用且占用大」时会出现两个阈值输入框，默认「未用超过 90 天，且 ≥ 200 MB」，可自行调整。这是找清理目标的最快方式。
- 右侧下拉框切换排序：按最近活跃 / 按空间占用。

### 4.4 详情面板

点击任意一行，右侧显示该项目详情。

**操作按钮**

| 按钮 | 作用 | 何时可用 |
| --- | --- | --- |
| 新会话 | 打开 PowerShell，进入项目目录运行 `claude` | 正常、仅配置 |
| 恢复会话 | 同上，运行 `claude --resume` | 正常、仅配置 |
| 打开项目路径 | 资源管理器打开真实路径 | 正常、仅配置 |
| 打开数据目录 | 资源管理器打开 `.claude\projects\<编码目录>` | 有数据目录的项目 |

孤儿项目、不可达、无主数据的路径相关按钮灰掉，避免误操作。

**信息区块**

1. **基本信息**：最近活跃时间、会话数、数据目录名、信任状态（是否在 CC 里点过信任此目录）。
2. **空间占用**：按类别列出大小、文件数、清扫策略、删除后果。转录类下方固定提示「转录为明文 JSONL」，提醒命令输出中的密钥会原样落盘。
3. **token（现存转录）**：输入、输出、缓存写入、缓存读取四项，加消息数与跳过的坏行数。下方注明口径：这是现存转录的用量，不是历史总量。
4. **记忆**：分两行。
   - **自动记忆（CC 写）**：`memory/` 下文件数与 `MEMORY.md` 行数。
   - **用户记忆（随项目文件夹）**：`CLAUDE.md`、`CLAUDE.local.md`、`.claude/rules/` 是否存在。孤儿项目无法检查。

## 5. 全局页

### 5.1 顶部四个数字

数据根合计大小、项目数、清扫周期（30 天默认值，或 `settings.json` 里显式设置的值）、无法访问的条目数。

### 5.2 按类别表

`.claude` 下所有数据按类别拆分，按大小降序。每类标注**清扫策略**，让你一眼看出哪些会自己消失：

| 清扫策略 | 含义 |
| --- | --- |
| N 天自动清扫 | CC 会按 `cleanupPeriodDays` 自动删除超期文件（转录、文件快照、粘贴缓存等） |
| 永久保留 | `history.jsonl`、`stats-cache.json` |
| 不参与清扫（记忆特殊规则） | 自动记忆 |
| 清扫时移除 | 旧版本遗留目录 |
| 受保护，工具不触碰 | 凭据、配置、插件、技能、全局记忆、会话文件等，本工具永不动它们 |
| 未知 | 不认识的目录，只展示大小 |

### 5.3 下次清扫模拟

按当前清扫周期，列出下次 CC 自动清扫会删除多少文件、释放多少空间、各类别多少。用来判断「等它自己清」还是「需要手动处理」。

### 5.4 token 总量

直接读取 CC 自己的 `stats-cache.json`（即 `/usage` 命令的数据）：会话总数、消息总数、统计截至日期、各模型的 token 四项。**本版本只显示 token 数，不换算金额。**

按钮：「打开 /insights 报告」打开 CC 生成的用量报告网页（需先在 CC 会话里执行过 `/insights`）；「打开数据根目录」打开 `.claude`。

## 6. 诊断页

排查问题时看这里。

| 区块 | 内容 |
| --- | --- |
| 基本信息 | 数据根路径与来源、配置文件路径（读取失败会标红）、`claude` CLI 路径与版本、工具自身数据目录（可一键打开）、视图生成时间 |
| 编码自校验 | 配置项数、当前规则匹配数、旧规则匹配数、无法解释的目录数及清单 |
| sessions/ 会话文件 | 每个会话文件的 PID、判定（运行中 / 僵尸文件 / 无法确认）、工作目录、状态、启动时间 |

**编码自校验是什么**：CC 把项目真实路径编码成数据目录名（如 `C:\a\b` → `C--a-b`），这个规则官方可能会改。工具用配置文件里的路径反推目录名做核对，如果出现两种规则都解释不了的目录，就显示「未通过」，并在后续版本里禁用迁移功能，防止把数据挪错地方。只读功能不受影响。

**僵尸文件是什么**：CC 退出时有时不清理 `sessions/<pid>.json`，Windows 之后可能把这个 PID 给别的程序。工具会核对进程是否存活、是不是 CC 的进程、启动时间是否吻合，三项都对才算运行中。工具不会删除这些残留文件（`sessions/` 受保护）。

## 7. 数据安全与工具自身数据

- 对 `.claude` 目录**只读**。全部写操作只落在工具自己的目录 `%LOCALAPPDATA%\CCProjectManager\cache\`（两份扫描缓存 JSON）。
- 缓存可以随时删除，下次启动会重新扫描。
- 「新会话 / 恢复会话」只是替你打开一个 PowerShell 并运行 `claude`，之后的行为与你手动运行完全一样。
- 工具不联网、不发送任何数据。

## 8. 常见问题

**打开后看到的数字有点旧？**
状态栏显示「上次扫描 N 前」时是缓存结果。点「重新扫描」即可，约 3 秒。

**CLI 标签是红色「未找到 claude CLI」？**
工具通过 `where claude` 查找命令，再退回 `%USERPROFILE%\.local\bin\claude.exe`。如果 CC 装在别处，M1 只影响诊断页展示，后续删除功能会依赖它。

**编码自校验显示「未通过」？**
到诊断页看「无法解释的目录」清单。通常是官方改了编码规则，或 `projects/` 下被手动放了东西。只读功能不受影响。

**某个项目显示「路径不可达」？**
它在网盘或 UNC 路径上，2 秒内没响应。连上网盘后重新扫描即可，工具不会把它当成孤儿。

**会话数和 token 为什么比预期少？**
转录受 CC 的 30 天自动清扫，工具统计的是现存转录。历史总量看全局页的 token 总量（stats-cache 口径）。

**同一个项目出现两行，一行「旧编码残留」？**
CC 升级后目录命名规则变了，旧目录留在原地。本版本只展示，合并或清理在后续版本。

**点「新会话」没反应？**
它会弹出一个独立的 PowerShell 窗口；如果 `claude` 不在 PATH 里，窗口会提示命令不存在。
